# OpenCodeX source-of-truth index

Use this index to find the owner of a behavior. Consumers derive from these sources; they do not restate their policy.

| SSOT type | Authoritative source | Derived consumers | No duplicate definitions |
| --- | --- | --- | --- |
| Logical preset routing and logical catalog projection | `src/routing/presets.ts` (`compileRoutingPreset`, `applyRoutingPreset`, `logicalModelCatalogRows`) | `src/routing/runtime-snapshot.ts`; runtime `/v1/models` projection; `scripts/switch-codex.ts` | Tests, qualification scripts, wrappers, and docs must construct expected routes/catalog via compiler or its projection. Do not copy provider/model/effort matrices or fallback order. |
| Provider/model capability registry | `src/providers/registry.ts`, `src/providers/registry/entries-core.ts`, `src/providers/registry/entries-extended.ts`; shared model families/seeds in `src/providers/registry/model-seeds.ts` | provider derivation/discovery and downstream catalog/capability views | Consumers may add provider-specific fixtures, but must not copy registry capability tables as a second source. |
| Captured runtime routing state and generation | `src/routing/runtime-snapshot.ts` (`RoutingRuntimeSnapshot`) | HTTP request preparation and WebSocket turn capture in `src/server/index/serve-options.ts` and `src/server/index/websocket-handler.ts` | A turn captures one snapshot/generation; consumers must not independently compile or mutate routing state. |
| Routing reload/state adoption | `src/server/local-routing-reload-client.ts`; management handlers in `src/server/management-api.ts`; capability contract in `src/lib/local-routing-reload-contract.ts` | `scripts/switch-codex.ts` and local management clients | Reload is a routing-projection adoption path. Do not create another control endpoint, authorization scheme, or runtime-state copy. |
| Public logical model catalog | `src/routing/presets.ts` and runtime `/v1/models` assembly in `src/server/management-api.ts` | API clients, tests, catalog display | `/v1/models` is derived output, not an independent routing/capability configuration source. |
| Production preset switching and rollback | `scripts/switch-codex.ts` | production `switch-codex` entrypoint and tests in `tests/cli/cli-switch-codex.test.ts` | The CLI consumes the compiler, snapshots config, invokes authorized routing reload, and verifies runtime state; it owns no route matrix. |
| Production service/deployment and package release | `scripts/release.ts`, `scripts/prepare-package.ts`, `package.json`, and `src/service.ts` plus `src/service/` platform service implementations | release package, immutable deployment artifact, systemd unit, operational wrapper | Deployment entrypoints bind operational paths and artifact provenance only; never duplicate preset or provider capability policy. |

When changing one of these owners, update its focused tests and any source-map documentation. Search for stale literals in tests and qualification scripts; fixtures should use the owning compiler/registry wherever a full expectation can be derived. A literal is appropriate only when it is the behavior under test (for example, asserting a specific compiled output), not as a second fixture configuration that can drift independently.
